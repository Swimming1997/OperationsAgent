> 版本：v1（2026-06-21）
> 定位：本文是**当前 Local-First 情报中心（剔除 AI）的事实来源与发布路线图**，回答"现在能不能给用户用、还差什么"。配套《产品需求文档 v2》《数据库设计 v1》《开发顺序与技术方案》。

## 0. 一句话结论

**单账号核心闭环已经可用（采 → 存去重 → 本地浏览筛选 → 加素材库），可以拉一两个员工做内测。**
但要"放心交给一线运营天天用、且多账号、且不封号"，还差 6 块 P0：**详情字段补全、多账号并发稳定化、反检测底线、打包分发、启停脚本稳健性、对标已读闭环**。预计这 6 块做完即达到"可灰度上线"。

## 2. 距离上线还要做（按优先级）

### P0 · 阻断"放心给一线天天用"

**P0-1 内容详情字段补全（关系到列表/详情展示完整度）**
- 现状：`body_text`、`image_urls` 已落库；但 `topics`(关联话题)、`platform_tags`(平台标签)、`video_duration`(视频时长)、`is_ad`(广告标识)、内容级 `ip_location` **列存在但未写入**（normalizer 已能提取 platform_tags 到 raw_payload，未落列）。
- 影响：PRD §5.3 的 A/B/C 三个列表/详情明确要展示"关联话题、笔记类型、发布时间、视频时长"，目前展示不全。
- 做法：`detail_normalizer.py` / `search_probe` 归一化结果 → 写入 `content.topics_json`/`platform_tags_json`/`video_duration`/`is_ad`/`ip_location`；前端详情页与列表补展示。

**P0-2 多账号并发稳定化（当前"形式上多账号、实际常单浏览器"）**
- 现状：`_run_detail_batch` 按"已登录且 CDP 可解析的账号"开 worker，但账号自己的 Chrome 没运行（或 Agent 重启后内存 CDP 映射清空）时，只剩默认浏览器 → 单 worker → 慢。已做去重 + 日志，但未解决"浏览器没起来"。
- 做法：批采前自动按所选账号**拉起/复用各账号浏览器**（`start_account_chrome` 复用），解析不到的账号给出明确提示；前端展示"本次实际并发 N 个浏览器 / 账号"。

**P0-3 反检测底线（上线即封号风险，技术方案 E0.4 / E2）**
- 现状：节奏控制 ~80%，但**账号级最低采集间隔 + 每日上限策略 = 0%**；`platform_accounts` 限速字段未落地执行。
- 做法：账号级 `min_interval_seconds` + `daily_quota` 落地并在采集/批采调度处强制执行（先写保守默认值），冷却触发时跳过该账号。

**P0-4 打包分发（员工怎么装上）**
- 现状：`package_project.bat` 存在，但"配置中央地址 → 注册接入 → 首次启动"的成品安装包 ~10%。
- 做法：产出可分发包（含 .venv 或自带 Python、Chrome 检测、首启配置中央 URL 与设备名）、写《员工安装与首启指南》。

**P0-5 启停脚本稳健性（双击 bat 必须稳）**
- 现状：`stop.ps1`/`Stop-LocalAgentStack` 不能识别 bridge 进程（实测残留旧进程、端口占用），`start_local_workspace.ps1` 读 URL 正则已修但脚本整体仍脆。
- 做法：用 PID 文件 + 端口归属双重判定可靠 stop；start 失败时给清晰指引；保证"双击启动/停止"对非技术员工可用。

**P0-6 对标"已读"闭环（红点要能消）**
- 现状：`POST /api/local/tasks/{id}/viewed` 端点 + `new_content_count` 已有，但**前端无"标记已读"按钮**，红点数字永远不清。
- 做法：对标监控项加"查看/标记已读"交互，点开即调用 viewed，清红点。

### P1 · 体验与完整度

- **P1-1 抖音接入本地工作台采集**：probe 齐全（feed/suggest/detail/comment/creator），但 `LocalCollectionService` 仅 XHS。PRD 口径"先小红书，抖音兼容"，可作为上线后第一个增量。
- **P1-2 单条详情字段在列表的展示**：监控时间 / 数据更新时间 / 笔记类型在列表的呈现对齐 PRD §5.3。
- **P1-3 获客自定义关键词**：前端 acquisition-check 未传自定义 keywords，加入可编辑获客词。
- **P1-4 素材库 promote 字段补全**：promote payload 带上 topics/platform_tags 等，避免素材库精华缺字段。
- **P1-5 首启引导/空状态**：员工首次打开先引导"登录平台账号 → 再采集"，减少懵。

### P2 · 增强（不阻断上线）

- 推荐流"定时刷新"复用同一任务而非每次新建。
- 本地标题检索上 SQLite FTS5（数据量大后再做）。
- 配置同步：对标/关键词配置 push 到中央 `creator_monitors`，换机可拿回（技术方案 S5）。
- 主管全局产出（远期，数据已在中央预留）。

## 3. 发布判定清单（Definition of Done）

灰度上线前逐项打勾：

- [ ] P0-1 详情字段补全：话题/平台标签/视频时长/广告/IP 已落库且前端可见
- [ ] P0-2 多账号批采实测：N 个账号 = N 个浏览器并发（日志 `detail-batch resolved N` 佐证）
- [ ] P0-3 反检测：账号级间隔 + 每日上限生效，超限自动跳过
- [ ] P0-4 打包：干净机器按指南装好、配置中央地址、注册成功、能采能看
- [ ] P0-5 启停：双击启动/停止稳定，无残留进程/端口占用
- [ ] P0-6 对标红点：能标记已读并清零
- [ ] 端到端：搜索→采集→详情→获客→加素材库 全链路一遍无错
- [ ] 全量测试：`local_agent` + 我们改动到的中央端点测试全绿
