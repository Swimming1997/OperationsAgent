# P2 开发落地计划 - Local-First 收敛方案

> 定稿日期：2026-06-14  
> 依据：P0/P1 验收文档、`待开发计划/` 下 2026-06-13 Local-First 草案、当前 central_server / local_agent / shared_contracts 实现。  
> 定位：本文是 P2 阶段唯一开发入口。若本文与 `待开发计划/`、旧性能计划或旧产品草案冲突，以本文为准。

---

## 1. 阶段结论

P0/P1 已完成的是“中央情报池 + Job 闭环 + 对标素材库”的可运行版本。P2 不推翻这些已验收能力，而是在它们之上收敛到 **Local-First**：

- 日常采集、全量内容存储、搜索/浏览优先在员工本地完成。
- 中央保留账号池、Agent 生命周期、配置同步、素材库精华沉淀、权限和审计。
- 采集能力继续走 `local_agent`，跨端协议继续优先进入 `shared_contracts/`。
- 中央和 Local Agent 边界保持不变：中央不得 import Local Agent runtime；Local Agent 不访问中央 DB/storage/services。

P2 的目标是把系统从“中央可用闭环”推进到“员工本地高频使用闭环”，同时减少中央并发压力和平台重复请求。

---

## 2. 已完成基线

以下能力作为 P2 的前置基线，不在 P2 重做：

- P0 对标库、情报筛选、批量入库、规则重评、权限矩阵已验收。
- P0 PostgreSQL 1 万条情报列表性能验收通过。
- P1 任务模板、运行中心、XHS 账号资产只读 Job、素材准备、规则解释、真实 SLO 报告按文档完成。
- XHS login / self_info / feed / search / detail / comments / creator 基础 smoke 已通过。
- 抖音已有 feed、suggest、detail/comment 方向的接入记录；具体正式能力以代码和测试为准。

## 3. P2 总目标

### 3.1 本地采存看闭环

- Local Agent 写本地 SQLite，而不是把全量流水都上报中央。
- 本地库按 `platform + platform_content_id` 去重，一条内容只存一份。
- 本地记录内容来源：搜索关键词、推荐流、对标博主、长尾词深挖。
- 本地 Web 提供搜索列表、对标博主列表、内容详情、采集中/完成/失败状态。

### 3.2 素材库联机沉淀

- 运营只在“收藏/加入素材库”时把精选内容上报中央。
- 中央复用 `reference_library_items` 等已落地模型，不新建平行素材库。
- 中央记录 owner、加入时间、标签、备注、评分和必要快照。
- 封面图只对素材库精华做缓存或代理，不做全量媒体下载。

### 3.3 反检测与账号保护

- 采集行为必须经过统一节奏控制，不把随机滚动/停留逻辑散落到各 connector。
- 落地账号级最低间隔、每日预算、失败退避、健康状态映射。
- XHS 与抖音共享平台无关的 pacing/risk 内核，平台适配层各自处理选择器、API、字段归一化。

### 3.4 平台能力补齐

- 小红书保持现有只读采集能力稳定，并补齐未验收字段。
- 抖音补齐 creator/profile、detail/comment、评论获客信号等能力到统一内容模型。
- 长尾词到内容深挖必须在本地任务链路里闭环，不先做只有探针没有落库/展示的断点能力。

### 3.5 中央轻量化与生产化

- 中央数据库继续支持 PostgreSQL 生产部署；SQLite 保留本地开发/测试默认。
- 中央 20+ 并发性能不再是 P2 的第一主线，但需要保留压测和优化路径。
- 中央高频查询优化、Agent 轮询退避、前端虚拟化作为 P2 后段或专项处理。

---

## 4. 非目标

P2 不做以下内容：

- 不做 AI 自动仿写、自动仿画、自动成稿。
- 不做自动发布、点赞、收藏、关注、评论、私信等动作能力。
- 不做跨员工全量内容公共池浏览。
- 不做媒体全量下载、指标历史快照、ES/分布式消息队列。
- 不开放 sales 对 `reference-library` 的写权限。
- 不把 `references/MediaCrawler` 当正式运行依赖。

## 5. 任务优先级

### P2-A 地基：本地库与本地 ingestion

1. 新建 Local Agent 本地 SQLite 存储模块，启用 WAL、busy timeout、foreign keys。
2. 建本地内容、作者、来源、评论命中、长尾词、采集任务、采集运行等表。
3. 将采集归一化结果写入本地仓库，保留失败重试和幂等 upsert。
4. 保持 Local Agent 与中央只通过 HTTP JSON 做注册、心跳、账号/配置同步和素材上报。

验收：

- 本地采集 XHS 搜索/详情/评论后可落本地库。
- 重复采集同一内容不会重复建内容，只更新最新指标和来源关系。
- 中央边界扫描仍通过。

### P2-B 第一闭环：本地 Web 搜索与详情

1. 提供本地 Web 入口，展示搜索任务、搜索结果列表、内容详情。
2. 搜索提交为异步采集任务，界面展示采集中、完成、失败。
3. 列表字段覆盖封面、标题、作者、点赞、评论、发布时间、来源、更新时间。
4. 详情字段覆盖正文、图片/视频 URL、互动指标、作者信息、话题/标签。

验收：

- 运营可在本地输入关键词，等待采集完成后浏览列表和详情。
- 本地 Web 不依赖中央内容查询 API。
- 本地 SQLite 单人几万条元数据列表可用，无明显卡顿。

### P2-C 对标监控与推荐流刷新

1. 本地 `collect_task` 支持 search、creator_monitor、recommend。
2. 对标博主定时监控，按上次查看时间计算新内容数。
3. 推荐流支持定时刷新和手动刷新。
4. 作者画像补齐粉丝数、获赞收藏、作品数、认证、简介、IP 属地等字段。

验收：

- 对标博主有新内容时本地界面显示红点/计数。
- 推荐流刷新不会重复写内容。
- 作者画像和作品列表能在本地页面关联展示。

### P2-D 获客信号与素材库上报

1. 单条内容支持手动触发评论采集。
2. 本地按关键词匹配“求推荐、怎么买、多少钱、链接”等获客信号。
3. 内容可标记获客力，展示命中数和命中评论。
4. 运营把精选内容加入中央素材库，复用 `reference_library_items`。

验收：

- 评论采集按需触发，不做全量自动评论采集。
- 加素材库后中央可看到 owner、标签、备注和必要内容快照。
- 素材库上报失败可重试，不丢本地收藏意图。

### P2-E 平台能力与反检测深化

1. 落地统一 `PacingController` / risk policy 执行层。
2. 接入账号冷却、每日采集预算、失败退避和账号健康状态。
3. XHS homefeed/search 优先稳定 API 或响应拦截，DOM 作为 fallback。
4. 抖音 detail/comment/creator 与 XHS 对齐到统一内容模型。
5. 失败分类、stale running job 回收、审计报告导出作为稳定性专项。

验收：

- 同一账号连续任务之间存在可配置冷却。
- 不同 profile 能跑出不同节奏。
- 风控/验证类错误会影响账号健康状态和后续派单。
- 改采集逻辑后 Local Agent smoke audit 通过。

### P2-F 中央性能与前端/轮询专项

1. PostgreSQL 生产部署文档、迁移和备份路径固化。
2. 需要时补 keyset 分页、搜索索引、热点缓存。
3. Agent claim/heartbeat 支持退避或长轮询评估，降低空转压力。
4. 前端列表虚拟化、筛选防抖、避免重复刷新风暴。
5. 清理已知预存失败测试，并纳入回归。

验收：

- 中央仍可支撑账号、Agent、配置和素材库的联机负载。
- 20+ Agent 在线时无明显 claim/heartbeat 风暴。
- 后端、前端、Local Agent 受影响测试通过。

## 6. 销售写权限预留

销售写权限仍为 P2 预留能力，但不和 Local-First 主线混做。

可选路径：

- `/api/leads/*`
- `/api/customer-intents/*`

边界：

- sales 可以更新客资/跟进域状态，例如 `contacted`、`qualified`、`closed`。
- sales 不获得 `reference-library` PATCH、入库、归档、撤回权限。
- 客资域需要独立 PRD、独立模型、独立权限矩阵和测试。

## 8. 工程红线

- 新跨端协议、枚举、payload 优先放入 `shared_contracts/`。
- 新本地存储代码放入 Local Agent 清晰模块，不 import 中央 storage/repository/service。
- 中央新增 API 路由必须放入对应 route 模块，不回堆到聚合大文件。
- 新 DB model 放入领域模型文件，`models.py` 只保留兼容导出和集中索引注册。
- 不绕过 `JobRepository` 或 `intelligence_engine.jobs` 修改 Job 生命周期字段。
- 涉及调度、账号登录、采集上报、数据库模型、权限、运行状态的改动必须补测试。
- 完成改动前至少运行受影响模块测试；跨模块或协议变更需运行对应全量测试或说明原因。
